# 制定实施计划

当开始复杂任务时，遵循以下流程：

## 适用场景

- 新功能开发（涉及多个文件）
- 代码重构（改变现有架构）
- 修复复杂 Bug（需要深入分析）
- 添加新的依赖或配置
- 任何可能需要返工的任务

## 不适用场景

- 单文件简单修改
- 文档更新
- 配置微调
- 明确且直接的任务

## 实施流程

### 1. 理解需求

- 理解用户意图，不要假设
- 搜索相关代码，查找可复用的实现
- 检查是否有类似的功能已存在

### 2. 探索代码库

- 使用 `grep` 搜索关键词
- 使用 `glob` 查找相关文件
- 阅读关键文件理解现有实现
- 记录可复用的函数、组件、模式

### 3. 制定计划

计划应包含：

```markdown
## 背景
- 为什么需要这个改动
- 解决什么问题

## 实施方案
- 分步骤描述（编号）
- 每个步骤涉及的文件
- 需要创建的新文件
- 需要修改的现有文件

## 可复用资源
- 已有的函数/组件列表及路径
- 相关的类型定义

## 验证方式
- 如何测试改动
- 运行什么命令验证
```

### 4. 请求确认

使用 `AskUserQuestion` 让用户确认方案：
- 如果方案有多个选择，列出选项
- 如果方案清晰，直接请求确认

### 5. 实施

获得确认后：
- 按计划步骤逐一执行
- 每完成一个步骤可以汇报进度
- 遇到问题及时沟通，不要强行绕过

## 计划文件格式

将计划写入 `docs/plans/plan-name.md`：

```markdown
# 计划标题

## 背景
简述为什么需要这个改动。

## 实施步骤

### 步骤 1: xxx
- 文件: `src/xxx.ts`
- 操作: 创建/修改
- 内容: ...

### 步骤 2: xxx
- ...

## 可复用资源
- `src/utils/formatDate.ts` - 已有日期格式化函数
- `src/components/UserCard.vue` - 可参考的用户卡片组件

## 验证
- 运行 `pnpm typecheck`
- 运行 `pnpm test`
- 手动测试: pnpm dev
```

## 注意事项

- 不要假设用户意图，有疑问先询问
- 不要跳过探索直接动手
- 不要过度设计，只做必要的改动
- 遇到阻塞不要强行绕过，先沟通

## 常见错误

- ❌ 不探索直接开始写代码
- ❌ 不确认方案直接实施
- ❌ 过度设计，添加不需要的功能
- ❌ 遇到问题不沟通，强行绕过安全检查
